## Собственный проект

Тема проекта: каталог игр

Главный класс: `Game`

Почему этот объект нужен программе:
Класс `Game` хранит данные об одной игре в одном месте и не нужно заводить отдельные переменные для названия, жанра, года выхода и рейтинга каждой игры. Благодаря классу в каталог можно добавить сколько угодно игр и каждая будет хранить собственные данные.

Какие данные хранит объект:

- `Name (string)` - название игры.
- `Genre (string)` - жанр игры.
- `Release_date (int)` - год выхода игры.
- `Rating (int)` - рейтинг игры.

Какие значения задаются через конструктор:
- `Genre (string)` - жанр игры.
Название (Name), жанр (Genre) и год выхода (Release_date). Эти данные у каждой игры свои, поэтому передаются при создании объекта.

Какие значения можно задавать автоматически:
Рейтинг (Rating). Конструктор сам присваивает ему начальное значение 10, поэтому передавать рейтинг при создании передавать не нужно.

## Практическая работа №2
1. **Почему при `yaroslav.TakeDamage(25);` не меняется здоровье Артёма и куда попадает 25?**
Метод работает с объектом слева от точки, то есть я Ярославом, поэтому Артём не меняется, мы не вызывали для него этот метод. Число 25 попадает в параметр `damage` и `Healt -= damage` даёт 100-25=75. В моём коде: `sky.ChangeRating(8)` передаёт 8 в `newRating` и меняет только `sky`.

2. **Чем отличаются `return;` в `TakeDamage` и `return Health > 0;` в `IsAlive?`**
`return;` просто завершает метод `void` досрочно и при неверном уровне здоровье не меняется. А `return Health > 0;` возвращает ответ `true` или `false`.

3. **Как получить строку о герое, не печатая её сразу? Какая строка программы печатает её позже?**
`string info = yaroslav.GetInfo();` сохраняет строку, а печатает её `Console.WriteLine(info)` в `Program.cs`.

Были добавлены пять методов:
1. `TakeDamage` - герой получает урон.
2. `Heal` - герой восстанавливает здоровье.
3. `GainExperience` - герой получает опыт.
4. `IsAlive` - проверка здоровья героя, жив ли он.
5. `GetInfo` - возвращает строку с информацией о герое.

Недопустимый крон проверен вызовом `yaroslav.TakeDamage(-20)` этом метод сработал через `return;`, здоровье Ярослава осталось 75. Сильный урон `artem.TakeDamage(200)` понизил здоровье Артёма до 0.

Итог запуска: у Ярослава здоровье 85 и опыт 65, у Анастасии здоровье 60 и опыт 0, у Артёма здоровье и опыт 0.

В собственном проекте было добавлено: метод `ChangeRating` который меняет рейтинг игры. Параметр `newRating` получает новое значение рейтинга (число от 1 до 10). Проверен отказ: `sky.ChangeRating(15);` отклонён, рейтинг остался 8 (был 10, после стал 8).

## Практическая работа №3

Ошибка 1: свойство `public int Health { get; set; }` позволяют записать `alexander.Health = -100;` из `Program.cs`. Исправлено на: `public int Health { get; private set; }`. Та же запись перестала компилироваться, после удаления строки программа запустилась.

Ошибка 2: в `set` свойства `Name` было `value.Trim(); _name = value;`, и пробелы оставались. Исправлено на: `_name = value.Trim();`, потому что `Trim()` возвращает новую строку. После исправления `" Александр "` вывелось как `[Александр]`.

1. **Чем отличается запрет внешней записи от проверки допустимого числа? Где проверяются здоровье при создании и его изменение?**
`private set` решает кто может записывать значение, но не проверяет число. Допустимость числа проверяют конструктор и методы внутри класса. В моём коде: `private set` у `Release_data` и проверка `< 1970` в конструкторе и в `ChangeRelease`.

2. **Как `Name = name;` связывает параметр конструктора, `value` и поле `_name`?**
В `Name = name;` аргумент попадает в параметр `name`, присваивание запускает `set` свойства `Name`, там значение становится `value`. После проверки и `Trim()` результат сохраняется в поле `_name`.

3. **Какие значения в проверках показали, что правило `0 <= Health <= MaxHealth` соблюдается?**
Правило `0 <= Health <= MaxHealth` показали значения: создание со здоровьем -100 дало 0/100, со здоровьем 5000 дало 200/200, лечение 5000 остановилось на 150, урон 5000 оставил 0, а `Heal(-20)` ничего не изменил.
